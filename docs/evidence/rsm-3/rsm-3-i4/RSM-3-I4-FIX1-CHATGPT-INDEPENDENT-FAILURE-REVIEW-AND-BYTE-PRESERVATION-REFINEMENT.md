## 3. Why blanket renormalization is rejected

Five of the six non-LF text paths are under:

`docs/evidence/**`

These files are historical/control evidence and their byte identities are part of the project evidence lineage.

Renormalizing CRLF/mixed bytes to LF would change historical evidence SHA-256 identities without changing semantic text.

That is not an acceptable side effect of a clean-clone portability correction.

The sixth path:

`compliance/THIRD_PARTY_NOTICES.html`

is a deterministic generated compliance artifact whose existing byte form is validated by the I3 compliance generator/checker.

Implicit EOL normalization at Git checkout/index level must not silently alter that generated byte baseline.

Therefore the correct policy is:

- normalize ordinary repository text to LF;
- explicitly preserve byte identity for historical evidence;
- explicitly preserve byte identity for the deterministic third-party notice artifact.

---

## 4. Refined `.gitattributes` policy

Authorized exact root `.gitattributes` content:

```text
* text=auto eol=lf
docs/evidence/** -text
compliance/THIRD_PARTY_NOTICES.html -text
```

with one final LF newline and no BOM.

Interpretation:

```text
ordinary text = repository-owned LF checkout
docs/evidence/** = byte-preserved, no Git EOL conversion
THIRD_PARTY_NOTICES.html = byte-preserved, no Git EOL conversion
binary/auto-detected non-text = not coerced
```

No existing tracked file is authorized to change.
